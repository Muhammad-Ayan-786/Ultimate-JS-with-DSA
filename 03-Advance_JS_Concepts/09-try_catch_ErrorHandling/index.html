Error Handling using try & catch

Error handling is a crucial aspect of software development, where you handle the unexpected and handle the error gracefully.

Important: try...catch works only with synchronous code, and only catches errors that happen in the same execution context. If an error occurs inside scheduled or asynchronous code (like setTimeout), the outer try...catch will NOT catch it.

try { // Synchronous operation with no error console.log("No errors, yeah!!"); } catch (error) { console.log("This will not run"); }
try { // Synchronous error (variable is not defined) console.log(Meow); } catch (error) { console.log("Error occurred in try-catch > console.log(Meow)"); }

✔ try...catch will catch the error here.
The message Error occurred in try-catch > console.log(Meow) will be printed because Meow is not defined and the code runs synchronously.

try { // Outer try-catch does NOT help with async errors setTimeout(() => { // Inner try-catch catches the error correctly try { console.log(Me); } catch (error) { console.log("Error occurred inside setTimeout"); } }, 3000); } catch (error) { console.log("This will not run"); }
try { // Error happens asynchronously setTimeout(() => { console.log(Me); }, 2000); } catch (error) { console.log("This will NOT catch the error"); }

❌ try...catch will not catch the error here.
The browser will throw: Uncaught ReferenceError: Me is not defined because the error happens after the try block has already finished executing.
